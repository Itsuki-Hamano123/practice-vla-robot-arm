# データセット（LeRobotDataset v3）の形式と扱い方

収集したデモ（`outputs/datasets/so101_pick_box`）の中身と、よく使う操作をまとめる。収集の手順は [README](../README.md)、設計上の決定は [設計.md](設計.md) 8 章。

## 1. ディレクトリ構成

```
outputs/datasets/so101_pick_box/
├─ meta/
│  ├─ info.json                          # 総エピソード数・総フレーム数・fps・特徴量の定義
│  ├─ stats.json                         # 正規化用の統計（平均・標準偏差など）
│  ├─ tasks.parquet                      # 指示文（"pick up the red box" など）の一覧
│  └─ episodes/chunk-000/file-000.parquet   # エピソードごとの索引（下の 2 章）
├─ data/chunk-000/file-000.parquet       # 全エピソードの observation.state・action・タイムスタンプ
└─ videos/
   ├─ observation.images.camera1/chunk-000/file-000.mp4   # 正面カメラ（全エピソードを連結）
   └─ observation.images.camera2/chunk-000/file-000.mp4   # 手首カメラ（同上）
```

## 2. エピソードは連結して保存される

v3 形式は**エピソードごとにファイルを分けない**。全エピソードを 1 つの parquet・1 つの mp4 に連結して持ち、ファイルが大きくなる（目安 100MB 超）と `file-001` に分かれる。そのため、フォルダを見ると 1 エピソードしかないように見えるが、100 件入っている（`meta/info.json` の `total_episodes`）。

エピソードの区切りは `meta/episodes/chunk-000/file-000.parquet`（1 エピソード 1 行）に入っている。

| 列 | 意味 |
|---|---|
| `episode_index` | エピソード番号（0 始まり） |
| `tasks` | 指示文。赤か青かはここで分かる |
| `length` | フレーム数 |
| `dataset_from_index` / `dataset_to_index` | `data/` の parquet 内でのフレーム範囲 |
| `videos/<カメラ>/from_timestamp` / `to_timestamp` | 連結した mp4 内での開始・終了時刻（秒） |

## 3. エピソードの一覧を見る

```bash
docker compose exec -T policy python -c "
import pandas as pd
d = pd.read_parquet('/ws/outputs/datasets/so101_pick_box/meta/episodes/chunk-000/file-000.parquet')
print(d[['episode_index', 'tasks', 'length']].to_string())"
```

## 4. 特定のエピソードだけを .rrd に変換する

`scripts/dataset_to_rrd.py` が、上のフレーム範囲・動画時刻でエピソードを切り出して変換する。

```bash
# 5・12・37 番だけ
docker compose exec -T policy bash -lc 'cd /ws && source /opt/ros/humble/setup.bash && python scripts/dataset_to_rrd.py --root outputs/datasets/so101_pick_box --episodes 5 12 37'
# 全エピソード
docker compose exec -T policy bash -lc 'cd /ws && source /opt/ros/humble/setup.bash && python scripts/dataset_to_rrd.py --root outputs/datasets/so101_pick_box --all'
```

出力は `outputs/rrd/dataset/episode_<番号>_<指示>.rrd`。開き方は [README](../README.md) の「挙動を rerun で見る」と同じ。

## 5. 不採用のエピソード

成功判定に通らない、または 10Hz にそろえるときの重複フレームが多いエピソードは、`<root>_rejected`（例：`outputs/datasets/so101_pick_box_rejected`）に同じ形式で保存される。`reject_reason` は `not_success` / `duplicates`。確認は上の 3・4 章の `--root` を差し替える。

## 6. 学習に使うときの注意

- 学習データの最小単位はフレーム。`lerobot-train` はエピソードをまたいで連結済みのデータからフレームを取り出す（エピソード境界は LeRobot が上の索引で処理する）。
- `lerobot-train` の `--steps` はデータ量から自動では決まらない（未指定だと固定の既定値）。1 エポック ＝ 総フレーム数 ÷ バッチサイズ ステップ。`scripts/train.sh` の既定（バッチ 32）で、100 件（10,398 フレーム）なら 1 エポック約 325 ステップ、20000 ステップで約 61 エポック。
