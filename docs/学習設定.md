# ファインチューニング の設定（`scripts/train.sh` / `lerobot-train`）

lerobot 0.4.0 の `lerobot-train` に渡している引数と、その値の理由。既定値は 0.4.0 のソース（`configs/train.py`、`policies/smolvla/configuration_smolvla.py`）で確認した。**「実測」と書いていない値は、まだ GPU で試していない見積もり**。

## 1. epoch ではなく step で指定する

`lerobot-train` に epoch 数を指定する引数はなく、学習の長さは `--steps`（バッチを 1 回流す回数）だけで決まる。データ量から自動では決まらず、未指定だと既定の 100,000 ステップまで回る。epoch は参考値としてログに出るだけ。

```
1 epoch ＝ 総フレーム数 ÷ バッチサイズ ステップ
今回：10,398 ÷ 32 ≒ 325 ステップ ／ 20000 ステップ ≒ 61 epoch
```

## 2. 指定している引数

| 引数 | 値 | 既定 | 理由 |
|---|---|---|---|
| `--policy.path` | `lerobot/smolvla_base` | — | 事前学習済みの SmolVLA から ファインチューニング する（設計.md 8 章） |
| `--policy.device` | `cuda` | — | GPU マシンで学習する。CPU では 1 ステップ 260〜290 秒（スモークテスト） |
| `--policy.push_to_hub` | `false` | true | Hub にアップロードしない（出力はローカルのみ） |
| `--dataset.repo_id` / `--dataset.root` | `local/so101_pick_box` / 収集先 | — | ローカルのデータセットを使う。repo_id は収集時（`collect.py`）と同じ名前 |
| `--rename_map` | camera1→camera1（恒等） | なし | データに camera3 が無く、モデルが期待する特徴量との不一致エラーになる。マップを渡すとチェックを回避でき、camera3 は無視される（スモークテストで確認） |
| `--dataset.video_backend` | `pyav` | torchcodec | 上の試走の結果のとおり、torchcodec が GPU 環境で読み込めないため |
| `--batch_size` | 32 | 8 | 下の 3 章 |
| `--steps` | 20000 | 100,000 | 下の 3 章 |
| `--policy.scheduler_decay_steps` | `--steps` と同じ | 30,000 | 下の 4 章 |
| `--num_workers` | 4 | 4 | データ読み込み（動画のデコード）の並列数。既定のまま。GPU が待たされるなら増やす |
| `--save_freq` | 2000 | 20,000 | 途中のチェックポイントも評価に使えるよう、細かく保存する（最後にも必ず保存される） |
| `--log_freq` | 100 | 200 | 学習曲線を細かく見るため |
| `--eval_freq` | 0 | 20,000 | `lerobot-train` の評価は LeRobot の gym 環境用で、Gazebo では使えない。評価は別に行う |
| `--wandb.enable` | `false` | false | 使わない |
| `--output_dir` / `--job_name` | `outputs/train/<名前>` | — | `outputs/` は git 管理外 |

## 3. batch_size と steps の大きさ

- 既定の学習率（`optimizer_lr` 1e-4）は変えていない。SmolVLA の既定設定のまま。
- **batch_size 32**：LeRobot の SmolVLA の案内は 64 ＋ 20000 ステップだが、この GPU（NVIDIA GPU、メモリ 16GB）で 64 が載るかは未確認のため、半分の 32 から始める。試走で 64 は載らないと分かったので 32 に決定。
- **試走の結果（2026-10-24、NVIDIA GPU 16GB）**：
  - バッチ 32：1 ステップ約 0.65 秒（更新 0.61 秒＋データ読み込み 0.03 秒）、GPU メモリ約 9GB。50 ステップで loss 0.156 → 0.111。**20000 ステップで約 3.6 時間**。
  - バッチ 64：メモリが 16,016MiB と上限に張り付き、100 ステップに 19 分たっても届かなかったので打ち切った（1 ステップ 11 秒以上）。**この GPU ではバッチ 32 が上限。**
  - `--dataset.video_backend=pyav` を指定している。既定の torchcodec は GPU 版が CUDA の NPP ライブラリ（`libnppicc.so.12`）を見つけられず読み込めないため（コンテナにインストールされていない）。
- **steps 20000**：上の案内に合わせた値（`train.sh` の既定）。`save_freq` を細かくして途中のチェックポイントを評価に使えるようにしている。**実際には締切の都合で 5000 ステップで学習した**（約 53 分。結果は [実験結果.md](実験結果.md)。目安のバッチ 64・20000 ステップ［バッチ 32 なら 40000］の約 1/8 で、本来はもっと学習時間が必要）。
- 試走の結果、1 ステップが遅ければ steps を減らす（締切に合わせる）。

## 4. 学習率のスケジュール

SmolVLA の既定は、最初の 1,000 ステップで学習率を上げ（warmup）、そのあと 30,000 ステップかけて 1e-4 → 2.5e-6 に下げる（cosine）。`--steps` を 30,000 未満にすると、**下がり切る前に学習が終わる**。そのため `scheduler_decay_steps` を `--steps` に合わせている（ステップ数を変えても自動で追従する）。warmup 1,000 は既定のまま。

## 5. SmolVLA で学習される部分

既定では、視覚エンコーダと VLM を凍結し、action expert と state の射影層だけを学習する（`freeze_vision_encoder`・`train_expert_only`・`train_state_proj`）。変えていない。そのため必要なメモリは小さめ。`chunk_size`・`n_action_steps` は 50 のまま（1 回の推論で 50 ステップ分の指令を出す。10Hz で 5 秒）。
